Installing LambCrypt

LambCrypt has no binary releases yet. Build it from source as described below. The project README has the full build reference.

macOS

You need an Apple silicon Mac running macOS 26 or later.

  1. Install the Xcode Command Line Tools and Homebrew, then the build dependencies: 
    xcode-select --install
brew install wxwidgets
  2. Configure the Apple Development identity and the FSKit Module provisioning profile for your Mac using the integrator checklist in the project's FSKIT-MIGRATION.md. Source your private signing environment and build the app: 
    git clone https://github.com/e3742526/LambCrypt.git
cd LambCrypt
./src/Build/build_lambcrypt_macosx.sh -b -s
    The app is written to src/Main/LambCrypt-FSKit.app. A -b build uses Homebrew's wxWidgets, so keep that package installed.
  3. Copy the signed app to /Applications and open it. In System Settings > General > Login Items & Extensions > By Category > File System Extensions, enable LambCrypt FSKit.
  4. Run the built-in algorithm self-tests and verify a mount and dismount using a disposable volume.

Linux

Install the dependencies listed in the Linux build guide, then run:

git clone https://github.com/e3742526/LambCrypt.git
cd LambCrypt/src
make                 # or: make NOGUI=1 for a console-only build
sudo make install

This installs /usr/bin/lambcrypt and the mount helper /usr/sbin/mount.lambcrypt. The source tree also has scripts that build lambcrypt and lambcrypt-console packages in .deb and .rpm format, and an Arch Linux package build.

FreeBSD 14 and later and OpenBSD 7.8 and later build the same way, with gmake instead of make.

Windows

LambCrypt has no Windows release. Its Windows source keeps VeraCrypt's driver and boot loader identities and would collide with an installed VeraCrypt. Use VeraCrypt on Windows; volumes are compatible either way.

First launch

The first time you run LambCrypt, it shows the license terms. Choose I Accept and Agree to Be Bound by the License Terms to continue. LambCrypt records your acceptance in its preferences folder and asks again only if the license text changes.

In Terminal, lambcrypt --text asks the same question. To accept the terms for scripts and other non-interactive use, run lambcrypt --text --accept-license once as each user that runs LambCrypt, including root for /etc/fstab mounts. Setting LAMBCRYPT_LICENSE_ACCEPTED=1 accepts the terms for a single process, for example in automated tests.

Moving from VeraCrypt

LambCrypt and VeraCrypt can be installed on the same system. They use different command names, app names and preferences folders.

  1. Dismount all volumes in VeraCrypt before mounting them in LambCrypt. Don't mount the same volume in both programs at once.
  2. Optional: to keep your settings, quit both programs and copy the XML files, such as Configuration.xml, Favorite Volumes.xml and Default Keyfiles.xml, from VeraCrypt's folder to LambCrypt's:
    • macOS: from ~/Library/Application Support/VeraCrypt to ~/Library/Application Support/LambCrypt
    • Linux and BSD: from ~/.config/VeraCrypt to ~/.config/LambCrypt
  3. Update scripts and fstab entries that call veracrypt or mount.veracrypt to use lambcrypt and mount.lambcrypt.

Your volumes stay as they are, and VeraCrypt can still open them. See LambCrypt and VeraCrypt for compatibility details and Uninstalling LambCrypt to remove it.
