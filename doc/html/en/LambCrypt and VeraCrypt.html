Documentation LambCrypt and VeraCrypt

LambCrypt and VeraCrypt

LambCrypt is not VeraCrypt. It is an independently maintained derivative of VeraCrypt. It is not affiliated with or endorsed by IDRIX, AM Crypto or the VeraCrypt project. Report LambCrypt problems to the LambCrypt issue tracker, not to VeraCrypt.

Many chapters of this guide come from the VeraCrypt documentation. Where they mention VeraCrypt, the description applies to LambCrypt too unless a page says otherwise.

Why the name changed

LambCrypt was renamed to comply with the licenses it inherits from VeraCrypt (see License):

  • The VeraCrypt License grants no right to use the VeraCrypt name, logo or trademarks, or any confusingly similar name.
  • The TrueCrypt License 3.0 forbids a modified version from containing the name TrueCrypt.
  • Neither license allows the original authors' names to be used to endorse a derived product.

A modified version therefore cannot be distributed as "VeraCrypt". The rename changes product names, icons, links and bundle identities only. It does not change the volume format, the encryption or the on-disk layout.

Compatibility with VeraCrypt volumes

Backward compatibility with VeraCrypt volumes is a fixed requirement of LambCrypt.

  • Volumes: LambCrypt uses the VeraCrypt volume format and the .hc extension. It opens file containers, partitions and devices created by VeraCrypt, including hidden volumes, with the same password, PIM, keyfiles and security tokens. It never converts or upgrades a volume.
  • Both directions: volumes created by LambCrypt open in VeraCrypt. A volume that uses Argon2id needs VeraCrypt 1.26.29 or later.
  • Algorithms: LambCrypt offers the same ciphers, cascades, hash algorithms and key derivation functions as VeraCrypt.
  • Header backups: header backup files are interchangeable between the two programs.
  • Existing mounts: on Linux, BSD and macOS, LambCrypt keeps VeraCrypt's mount-tracking and lock identifiers, the default mount directories and the VERACRYPT_MOUNT_PREFIX variable.
  • File association: on macOS, LambCrypt claims .hc files under VeraCrypt's type identifier org.idrix.veracrypt.hc.

Preferences and favorites are not shared. See Moving from VeraCrypt.

FSKit

FSKit is Apple's framework for file systems that run as app extensions in user space. The FSKit macOS build of LambCrypt decrypts the volume in a worker process and serves the decrypted image through a sandboxed FSKit module, so macOS mounts it without macFUSE or FUSE-T. Unpartitioned FAT volumes use Apple's own msdos driver. Enable LambCrypt FSKit in System Settings and verify a disposable-volume mount on your Mac before relying on it.

Additional fixes

  • Volume headers are flushed to stable storage before the backup header is written.
  • Exporting a header backup never truncates an existing backup file first.
  • A failure while expanding a volume no longer leaves its size and headers disagreeing.
  • The Unix elevated service, AppImage elevation and FUSE-T auxiliary mounts have stricter checks.
  • An out-of-range PIM is rejected instead of overflowing, and a cancelled key derivation is reported as cancelled.

The project's BUGLOG.md lists every fix with its regression check.

Windows

LambCrypt has no Windows release. The Windows chapters of this guide describe VeraCrypt for Windows and are kept for reference. On Windows, use VeraCrypt; volumes are compatible either way. The Windows source has been renamed to LambCrypt but has not been compiled or tested, and its EFI boot loader binaries still come from VeraCrypt.
