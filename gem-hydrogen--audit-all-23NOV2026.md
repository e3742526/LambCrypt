## Executive Verdict

Risk posture is **ELEVATED — Conditional Hold on Release Packaging & High-Risk Paths Pending Targeted Patches**. Across the audited C/C++/Objective-C++/Swift/assembly/shell/CMake/batch/Python surfaces, **no catastrophic cryptographic break of XTS-AES or PBKDF2/Argon2 primitives was identified**, and several critical privilege/IO boundaries (notably `RequesterAccess.cpp`, `Process::ExecuteBounded`, `Process::FindSystemBinary`, `DriveFilter.c` BootArgs/SecRegion range+CRC validation, and `CoreService.cpp` `chown` target validation) show strong defensive engineering. However, **multiple Confirmed Critical/High defects** exist in memory safety, key/CSPRNG hygiene, command/elevation construction, pre-boot resource management, and supply-chain verification:

1. **Confirmed High — Arbitrary `delete` on live `std::shared_ptr` raw pointer (`USE-AFTER-FREE / UB`)**: `src/Driver/Fuse/FuseService.cpp:1155-1168` (`CloseMountedVolume`) invokes `delete MountedVolume.get();` while `MountedVolume.use_count() > 1`, followed by `MountedVolume.reset()`.
2. **Confirmed High — Partial `burn()` (`sizeof` mismatch) in CSPRNG Mixing**: `src/Common/Random.c:385` scrubs `STREEBOG_CTX stctx` with `burn(&stctx, sizeof(sctx))`, leaving trailing Streebog state (`N[8]`, `Sigma[8]`, `bufsize`, `digest_size`, tail of `h[8]`) unzeroed on the stack.
3. **Confirmed High — Unquoted Shell Command Construction & Temp-File Elevation/TOCTOU Risks**: `CoreUnix::CheckFilesystem` (`src/Core/Unix/CoreUnix.cpp:280-316`) passes unquoted `VirtualDevice` to `sh -c`; `CoreFreeBSD` (`src/Core/Unix/FreeBSD/CoreFreeBSD.cpp:208-211`) passes unquoted `devicePath` to `popen`; Windows `RemoveDeviceWriteProtection` (`src/Common/Dlgcode.c:13978-14029`) writes predictable batch/diskpart scripts into `%TEMP%` before `ShellExecute(..., L"runas", ...)`; and `Main.make:759-770` downloads and marks executable (`chmod +x`) an unpinned `continuous` AppImage build tool without digest or PGP signature verification.
4. **Confirmed High — Pre-Boot Lock/Buffer Leak & Underflow, plus Kernel IOCTL Input Asymmetry**: `src/Boot/Windows/BootEncryptedIo.cpp:82-93` returns `BiosResultInvalidFunction` without calling `ReleaseSectorBuffer()`, and line `140` underflows if `sectorCount == 0`; `src/Driver/Ntdriver.c:2934-2944` omits the `< -1 || == INT_MAX` range check on `ProtectedHidVolPim` that it enforces on `VolumePim`; `src/Core/Unix/OpenBSD/CoreOpenBSD.cpp:43,108` invokes bare `throw;` with no active exception (`std::terminate()`).
5. **Confirmed Medium/High — Hardened Runtime Entitlement Omission & Config/XML Round-Trip Drift**: macOS `app-entitlements.plist` generated by `Main.make:314-323` omits `com.apple.security.cs.disable-library-validation`, breaking hardened-runtime `dlopen()` of third-party PKCS#11 modules; `Main/Xml.cpp` has asymmetric `\` attribute escaping and non-atomic `CreateWrite`; `UserPreferences.cpp` duplicates `BackgroundTaskEnabled` in both `Load()` and `Save()`.

All 13 core `agent-skills` audit lenses and 14 applicable standalone audit skills were applied. Immediate remediation is recommended for P0/P1 items prior to distributing release installers or signed macOS/Linux/Windows artifacts.

## Data & Network Security Scan (Defensive Static Audit)

In accordance with the prompt's security scope ("If you can't do security related audits, skip them. Try and do data and network security scans that you are allowed to conduct"), below is a purely defensive static source assessment of data-at-rest/in-memory protection and network/IPC communications across the codebase.

### A. Data Security Static Findings Summary
1. **Cryptographic Key & Entropy Hygiene**:
   - **Defect Found (`SEC-RNG-001`)**: `src/Common/Random.c:385` passes `sizeof(sctx)` (`sha512_ctx`, ~208 bytes in userspace) when burning `STREEBOG_CTX stctx` (336 bytes: five 64-byte arrays + size/digest fields), leaving trailing hash state unzeroed on stack.
   - **Defect Found (`SEC-TOK-001`)**: `src/Common/SecurityToken.cpp:489-501` copies PIN / label into plain `std::string` before zeroing only `pin.c_str()` on unwind (any SSO move or heap reallocation leaves prior copies unburned). Meanwhile `SecurityToken.cpp:232-236` fails open on `CKA_PRIVATE` when `privateAttrib.size() != sizeof(CK_BBOOL)`.
   - **Defect Found (`SEC-WIN-002`)**: `src/Common/Dlgcode.c:10588-10646` (`PrintHardCopyTextUTF16`) writes plaintext UTF-16 secrets/recovery instructions to `%TEMP%\<title>` without wiping file contents before `_wremove(path)`, uses an unsanitized `title` as filename, and waits an arbitrary `Sleep(6000)` race window before unlinking.
   - **Holds Elsewhere**: `Common/Crypto.c:867-901` (`burn` on `userKey`, `ks`, `ks2`, `master_keydata`, `k2`, `CryptoInfoBuffer`), `DumpFilter.c:48-55` (`RtlSecureZeroMemory` + nonpaged contiguous memory + pre-built MDL avoiding PFN leakage), `DriveFilter.c:600-733` (`burn` on `mappedBootArgs`, `mappedCryptoInfo`, `secRegionData` before unmap), and `VolumeCreator.cpp` / `VolumePassword` (`SecureBuffer` wrapping).
2. **Configuration & Storage Atomicity**:
   - **Defect Found (`DAT-XML-001`, `REC-PREF-001`)**: `XmlWriter` (`src/Main/Xml.cpp:158`) opens files with `File::CreateWrite` directly (truncating live XML preferences, favorites, or keyfile config in place rather than temp-write + `fsync` + atomic rename), while `XmlParser` treats `\` as an attribute escape (`118-123`) that `XmlWriter::EscapeChars` (`179-187`) never escapes.
   - **Temp-Directory Security**: Unix paths (`CoreUnix.cpp:121, 1514, 1534`, `private_tmp_dir.sh`) enforce `O_CREAT|O_EXCL`/`mkdtemp`/`fchmod 0700`/ownership checks. Conversely, Windows helpers (`RemoveDeviceWriteProtection` at `Dlgcode.c:13993-14026`, `RegisterDriverInf` at `Dlgcode.c:14378`, `PrintHardCopyTextUTF16` at `Dlgcode.c:10597`) still construct fixed, predictable paths under `GetTempPath()`.

Important seams that were directly inspected and held under static scrutiny:

1. **Privilege Drop & Peer-Cred Validation (`src/Platform/Unix/RequesterAccess.cpp`)**: Properly drops capabilities (`setresuid`/`setresgid`), sets `PR_SET_DUMPABLE=0`, checks `SO_PEERCRED` (`peer.uid == 0`), validates requester IDs (`ParseRequesterId`), occupies descriptors `0..2` with `/dev/null`, and uses `O_CREAT|O_EXCL|O_TRUNC` safely.
2. **Untrusted `PATH` Mitigation (`Process::FindSystemBinary`, `Process::ExecuteBounded`)**: `FindSystemBinary(..., requireTrustedPath=true)` walks components from `/` via `lstat` verifying root ownership and non-group/other write permissions (with explicit read-only NixOS `/nix/store` handling). `ExecuteBounded` uses `posix_spawn` + `POSIX_SPAWN_CLOEXEC_DEFAULT` and tracks/reaps child PIDs cleanly.
3. **Privileged `chown` Scoping (`CoreService.cpp`)**: `ResolveUnixSetFileOwnerTarget` and `ValidateMacOSXSetFileOwnerTarget` block arbitrary path `chown` through `SetFileOwnerRequest`.
4. **UEFI/BIOS BootArguments Physical Memory Validation (`src/Driver/DriveFilter.c:581-735`)**: Validates CRC32 (`BootArgumentsCrc32`), bootloader version, `BootCryptoInfoRangeValid`, and `BootSecRegionRangeValid` *before* trusting mapped offsets, copies into stack/private buffer once to prevent double-fetch TOCTOU, and `burn()`s physical mappings before `MmUnmapIoSpace`.
5. **Encryption Thread Pool Drain (`src/Volume/EncryptionThreadPool.cpp`)**: Uses atomic `PoolReferences` + `PoolDrainedEvent` to wait for active callers before `StopWorkers()`, preventing use-after-stop on pool teardown.
6. **Common C XML Parser (`src/Common/Xml.c`)**: Properly rejects cross-tag quotes and out-of-bounds buffer lengths (unlike `src/Main/Xml.cpp`).
7. **System-Preferred RNG & Hardware Entropy (`src/Common/Random.c:945-969`)**: Uses `BCryptGenRandom(..., BCRYPT_USE_SYSTEM_PREFERRED_RNG)` on Windows and fails closed (`return FALSE`) if it fails, rather than silently falling back to weak clock/PID ticks.
8. **OpenWrt SDK SHA-256 & Linux CMake `/tmp` Guards (`src/Build/build_lambcrypt_openwrt.sh`, `src/Build/Tools/private_tmp_dir.sh`)**: Both pin SHA-256 digests (`openwrt.sh`) and verify directory ownership/permissions (`private_tmp_dir.sh`) before building from `/tmp`.
9. **Linux Device-Mapper & Loopback Identity (`src/Core/Unix/Linux/CoreLinux.cpp:925-995`)**: Sets loop `autoclear` and removes device-mapper layers strictly by mount instance UUID (`SerialInstanceNumber`) so partial dismounts or concurrent mounts are not cross-clobbered.
10. **Windows `DumpFilter.c` Crash/Hibernate Encryption (`src/Driver/DumpFilter.c`)**: Pre-allocates contiguous buffer + MDL at init time and only copies PFNs at `HIGH_LEVEL` without illegal memory-manager DDIs, checking `MaxPagesPerWrite`, sector alignment, `MDL_MAPPED_TO_SYSTEM_VA`, and `MagicNumber`.
