# LambCrypt bug log

| Location | Symptom | Fix | Regression check |
| --- | --- | --- | --- |
| [`src/Makefile`](src/Makefile) | On a fresh macOS checkout, `make bundle` entered the app directory before building the core libraries and failed with undefined symbols. | Build the project before assembling the bundle. Pass the appropriate target to each component. | Built `bundle` without prebuilt core libraries in separate macFUSE and FSKit source trees on macOS 26.6.2. Both builds linked and passed the crypto self-tests. |
| [`src/Driver/Fuse/FuseService.cpp`](src/Driver/Fuse/FuseService.cpp) | A read starting past the volume's logical end could underflow its requested length. | Share bounds-checked byte reads in the volume layer. Return EOF before subtracting the offset, and reject negative FUSE offsets. | The SHA-512 fixture test checks unaligned reads, reads crossing EOF, offsets at and past EOF, and the maximum offset. The decrypted image matches the known SHA-256 digest. |
| [`src/Driver/FSKit/FSKitService.mm`](src/Driver/FSKit/FSKitService.mm) | A mount request rejected by macOS could leave an auxiliary socket directory after the client exited. | Detach the worker from the client's session and wait for its startup cancellation before returning the mount error. | Repeated the mount with the extension disabled and verified that the failure left no mount, worker process, or service directory. |
| [`src/Driver/FSKit/VolumeProtocol.cpp`](src/Driver/FSKit/VolumeProtocol.cpp) | A client reused the socket pathname on each request. A replacement worker at the same pathname could supply bytes for a different mount. | Bind image reads, control reads, and subsequent inspections to the worker UUID negotiated at mount. Version the request to reject older workers that lack this check. | [FSKit protocol test](Tests/test_fskit_volume_protocol.py) verifies stale requests return `ESTALE` after replacing the fixture worker at the same pathname. |
| [`src/Driver/FSKit/VolumeProtocol.cpp`](src/Driver/FSKit/VolumeProtocol.cpp) | FSKit used random UUID bytes for the mount serial, so mounts could sort out of creation order. | Generate the serial using the FUSE wall-clock units and retain the UUID for protocol identity. | [FSKit protocol test](Tests/test_fskit_volume_protocol.py) checks that a later worker reports a larger serial and that both serials fit their startup time windows. |
| [`src/Driver/FSKit/Info.plist`](src/Driver/FSKit/Info.plist) | macOS recognized the enabled extension and refused its mount operation. | Declare the activation options used by the system mount command. | The disposable VeraCrypt mount reached the FSKit resource probe and attempted to launch the extension. |
| [`src/Main/Main.make`](src/Main/Main.make) | The signing recipe skipped the nested FSKit extension. macOS refused to launch the extension when the FSKit capability lacked a provisioning profile. | Sign the extension before the app. Embed an Apple-issued profile for the exact extension bundle ID and use its application and team entitlements. | Exercised the missing-profile and mismatched-profile build failures. Strict signature verification passed with the matching profile, and macOS launched the signed FSKit extension. |
| [`src/Main/TextUserInterface.cpp`](src/Main/TextUserInterface.cpp) | The terminal truncated a mount error at the first non-ASCII character, including paths containing a curly apostrophe. | Encode text UI output as UTF-8 so the complete diagnostic reaches the terminal. | Attempted to mount a nonexistent fixture path containing `’`. The command exited 1 and printed the full path and trailing newline. |
| [`src/Main/Main.make`](src/Main/Main.make) | The Swift entry point returned before the extension could accept FSKit's XPC connection. | Use the system extension entry point that Xcode selects for this target type. | The Makefile-built extension started and handled the live resource probe. |
| [`src/Driver/FSKit/FSKitService.mm`](src/Driver/FSKit/FSKitService.mm) | App Sandbox denied the extension's connection to the volume worker's Unix socket in the temporary directory. | Put the private socket in a team-scoped app group shared by the signed app and extension. | A live FSKit mount read the known VeraCrypt payload and a fresh macFUSE-created volume. The external dismount test checked background-app exit and release of the backing file. |
| [`src/Core/Unix/MacOSX/CoreMacOSX.cpp`](src/Core/Unix/MacOSX/CoreMacOSX.cpp) | A writable FSKit test image stalled in macOS disk detach after its inner FAT mount disappeared. The CLI kept waiting. | Bound the FSKit detach and auxiliary unmount commands. Report unconfirmed teardown and stop at the timed-out step. | [macOS discovery and teardown test](Tests/test_macos_discovery.py) injects both timeouts, verifies busy-volume handling, and checks successful cleanup ordering. A read-only decrypt of the disposable backing file matched the test payload. A fresh post-restart run reproduced the stall with `diskutil unmount` before disk image detach. |
| [`src/Driver/FSKit/VolumeConnection.swift`](src/Driver/FSKit/VolumeConnection.swift) | FSKit could consume bytes after a short or failed read, leaving stale contents in unread parts of the requested buffer. | Zero the portion of the requested buffer that the worker did not fill, including on error. Preserve the actual byte count. | [FSKit protocol test](Tests/test_fskit_volume_protocol.py) uses prefilled buffers and a disposable VeraCrypt fixture to check short reads, EOF, and a stale generation error. |
| [`src/Driver/FSKit/FileSystem.swift`](src/Driver/FSKit/FileSystem.swift) | Closing the decrypted disk image could leave writes buffered until the next volume sync. FSKit provides no per-file sync callback. | Flush through the volume worker when FSKit releases write access to the image. | A direct callback test on a disposable VeraCrypt fixture verified a final writable close, skipped flushes on read-only and control items and while write access remained, and reported a stale worker generation. Live dismount remains pending. |
| [`src/Common/Language.xml#L1689`](src/Common/Language.xml#L1689) | The disk detach deadline returned an error that incorrectly claimed macOS had removed the auxiliary mount. | Report that dismount is unconfirmed and warn that the volume and its keys may remain accessible. | Reproduced the deadline on a fresh disposable FAT volume without an earlier busy attempt. Verified the updated English resource in the rebuilt scratch app and reran the injected detach and auxiliary unmount timeout tests. |
| [`src/Core/Unix/MacOSX/CoreMacOSX.cpp#L761`](src/Core/Unix/MacOSX/CoreMacOSX.cpp#L761) | FSKit attach could wait indefinitely for Disk Images. A timed-out attach can still complete in macOS. | Apply a 30-second child-process deadline per attempt. Report unconfirmed cleanup and keep the backing service available for safe later dismount. | [macOS discovery and teardown test](Tests/test_macos_discovery.py) detected the missing deadline before the patch and now checks timeout translation and the normal read-only attach flags. |
| [`src/Core/Unix/MacOSX/CoreMacOSX.cpp#L770`](src/Core/Unix/MacOSX/CoreMacOSX.cpp#L770) | An error that continued to mention `noautofsck` could make the compatibility retry loop indefinitely. | Retry only while the unsupported option is still in the command. | The same offline test checks that a single rejection can recover and that a second rejection propagates. |
| [`Tests/fskit_volume_protocol_test.cpp#L17`](Tests/fskit_volume_protocol_test.cpp#L17) | The protocol fixture opened the volume before detecting CPU features, so it missed the accelerated Apple Silicon path that the application uses. | Initialize feature detection before opening the disposable fixture, matching the application entry point. | The optimized [FSKit protocol test](Tests/test_fskit_volume_protocol.py) passed on Apple Silicon, including the fixture digest, short and failed reads, writes, synchronization, and stale worker rejection. |
| [`src/Core/Unix/CoreUnix.cpp#L1711`](src/Core/Unix/CoreUnix.cpp#L1711) | FSKit startup rollback searched by container path. It could select a replacement worker or suppress an error while the original worker still held the volume. | Retain the worker’s serial and auxiliary path from startup. Use the existing identity-checked dismount path, report unconfirmed cleanup, and preserve the worker after an unconfirmed attach. | The [offline startup rollback test](Tests/test_macos_discovery.py) reproduced replacement selection on the previous revision and verifies the captured identity and failure reporting. A live rejected read-only attach kept the original error and released the worker and auxiliary mount. |
| [`src/Driver/FSKit/FSKitService.mm#L223`](src/Driver/FSKit/FSKitService.mm#L223) | An auxiliary mount helper could outlive its timeout, and startup errors could conceal an unconfirmed worker exit or a remaining mount. | Use the bounded process runner. Report unconfirmed cleanup when the worker, mount table, or endpoint cannot confirm it. Keep the activation guidance after a confirmed rejection. | The [offline macOS test](Tests/test_macos_discovery.py) found the old helper path and now checks the deadline, worker timeout, unavailable mount table, remaining mount, and endpoint removal failure. A live read-only HFS+ mount verified payload and cleanup through the new helper. |
| [`src/Volume/VolumePasswordCache.cpp#L17`](src/Volume/VolumePasswordCache.cpp#L17) | The GUI could inspect the ordinary password cache while a mount thread changed its list. Cache reads and wipes also lacked mutual exclusion with stores. | Lock access to the list, including the copy returned to mount callers. Make the macOS release proxy rebuild when the cache header changes so an incremental build picks up the synchronized methods. | [ThreadSanitizer regression](Tests/volume_password_cache_test.cpp) reported a race before the fix and passed after it. It also verifies that wiping empties the cache and leaves a caller-owned snapshot valid. |
| [`src/Driver/FSKit/VolumeConnection.swift#L27`](src/Driver/FSKit/VolumeConnection.swift#L27) | A missing resource or an exited worker returned `EACCES`, which made a missing path look like a permissions failure. | Preserve `lstat` errors and retain `EACCES` for paths that fail the ownership, mode, or type checks. | The [protocol test](Tests/test_fskit_volume_protocol.py) reproduced the wrong error and now verifies missing resources and vanished sockets, rejected paths, and scrubbing the read buffer after a worker exit. |
| [`src/Driver/FSKit/VolumeProtocol.cpp#L139`](src/Driver/FSKit/VolumeProtocol.cpp#L139) | An empty protocol write tried to allocate a zero-length buffer and returned `EIO` before checking volume protection or the offset. | Skip buffer allocation and receipt for an empty payload while applying the normal write checks. | The [protocol test](Tests/test_fskit_volume_protocol.py) reproduced the error and now checks empty writes on read-only volumes, at EOF, and past EOF. The fixture's original digest also verifies that empty and truncated writes leave its data intact. |
